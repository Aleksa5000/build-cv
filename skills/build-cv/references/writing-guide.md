# Writing guide

Goal: a CV that sounds like a strong professional wrote it, and every line of it is **true**.

## Honesty rules (most important)

- **Never invent** metrics, users, revenue, team size, employers, dates, degrees or skills. If a strong line needs a number you don't have, **ask the user** ("How many people use it?", "How much faster did it get?"). If they don't know, write the line without a number.
- Only list a technology as a skill if the user's projects actually use it (you saw it in the code) or the user says they know it.
- "Built" means the user built it. If the git history shows other authors, ask what *they* did, and describe only their part ("Built the payment flow in a team of 3").
- AI-assisted work is real work. Don't hide it and don't apologize for it. If the user wants, mention it as a skill: "AI-assisted development (Claude Code): spec → review → test". Never claim deep knowledge of code the user can't explain; suggest `/explain-stack` and `/mock-interview` to close that gap.

## Project entry format

```
<Project name> · <one-line pitch: what it is and for whom>          <Month YYYY – Month YYYY | Present>
<link to repo or live demo, if public>
- <Action verb> + <what> + <how / with what tech> + <result or why it matters>
- <2–4 bullets total, most impressive first>
Tech: <5–10 main technologies, most relevant first>
```

Good bullets (start with a strong verb, concrete, short):
- "Built a spaced-repetition engine that schedules reviews on a 1–60 day ladder based on answer streaks (Python, FastAPI)."
- "Designed and trained a custom U-Net-style segmentation model from scratch in PyTorch to locate defects on X-ray images, with tiling for large scans."
- "Added an access gate with HMAC-signed approval links and rate limiting, protecting the platform behind email approval (Node.js, Express)."
- "Wrote 20+ automated tests (pytest) covering auth, licensing and sync."

Weak bullets to rewrite:
- "Worked on the backend" → what exactly, with what, and why it mattered.
- "Used React, Node, MongoDB" → that's the Tech line, not a bullet.
- "Responsible for…" → say what you *did*.

Keep each bullet to **1–2 lines** on the page (about 25 words max). One idea per bullet; split or cut long ones.

Strong verbs: built, designed, implemented, automated, integrated, reduced, improved, migrated, deployed, tested, secured, optimized, led, shipped.

## Which projects and what to highlight

Rank by: relevance to the target role → complexity and real problems solved → finished and usable → public (link) → recent. A junior CV usually has 2–4 projects. Ask before dropping anything the user added before.

Highlight what employers look for: real users or a real business need, deployment, auth and security, data modeling, tests, integrations (payments, email, AI APIs), performance, and own algorithms.

## Sections and order

1. **Header:** full name, title line (e.g. "Junior Full-stack Developer"), location (city, country; or "Remote"), email, phone (optional), links (GitHub, LinkedIn, portfolio).
2. **Summary:** 2–3 sentences: who they are, what they build, what they're looking for. No clichés ("hard-working team player").
3. **Skills:** grouped (Programming languages · Frameworks · Data · Tools · AI). Only real skills. Call the group "Programming languages", never just "Languages", so it isn't confused with the spoken Languages section.
4. **Projects:** for juniors and career changers, put Projects **before** Experience.
5. **Experience:** jobs, freelance, internships (also non-IT jobs, briefly, if the user wants: they show reliability).
6. **Education** and **Certificates/Courses**.
7. **Languages** (spoken), e.g. "Serbian (native), English (B2)".
8. Optional: Volunteering, Awards, Interests (one line).

## Style

- **Length:** 1 page for juniors, maximum 2.
- **Tense:** past tense for finished work, present for ongoing ("Building…"). No "I" in bullets.
- **ATS-friendly:** one column, real text (not text inside images), standard section names, no tables for layout, common fonts. Include keywords from the target role naturally.
- **Consistent:** same date format everywhere, same punctuation, same tense.
- **Personal data:** photo, date of birth and marital status are common in some countries (much of Europe) and discouraged in others (US, UK, Ireland, Canada). Mention this once and let the user decide. Never add a date of birth, nationality or marital status unless the user asks.

## Language

Write the CV in the language(s) the user chose. For an English CV, use natural professional English, even if the conversation is in another language. When the user chose two languages, both versions come from the same data and say the same things.
